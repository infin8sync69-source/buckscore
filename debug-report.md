# Bucks Browser — End-to-End Debug Report

Scope: `bucks browser/electron/` (canonical Electron app), `bucks browser/ipfs/`, `bucks browser/agent/`. All fixes were made directly in source and verified by actually launching the app (`npx electron .`) and reading its stdout/console output — not just static review. `npm audit` was run before and after.

---

## Electron Main / Security

- ✅ **No Content-Security-Policy was set anywhere** → Added a CSP via `session.webRequest.onHeadersReceived` in `main.js`, scoped **only** to the trusted shell document (`file://.../index.html`) — not applied to `bucks://` mini-apps or to WebContentsView tabs, which must stay free to render arbitrary sites under their own (or no) CSP. Verified live: caught a real violation on first launch (Google Fonts stylesheet blocked by `style-src`), fixed by allowing `fonts.googleapis.com`/`fonts.gstatic.com`, then confirmed a clean second launch with zero CSP violations logged.
- ✅ **My first CSP draft was itself a regression** — an Explore-agent frontend audit caught that scoping the CSP to all `bucks://` mainFrame docs would silently kill inline `<script>` blocks in `bucks-calc.html`, `bucks-notes.html`, `bucks-clock.html`, `bucks-converter.html`, `bucks-qr.html`, `bucks-template-dashboard.html`, and `bucks-template-portfolio.html` (all fine today, none have JS errors, none have their own CSP). Narrowed the CSP filter to `file://*/*` + `endsWith('/index.html')` only, so it can never touch a `bucks://` document. `bucks-qr.html` also loads a cdnjs script — unaffected now, but flagged below as a future hardening candidate if these mini-apps ever get their own CSP.
- ✅ **`contextIsolation`/`nodeIntegration`/`webSecurity`** — already correct everywhere (`main.js`, `tab-manager.js`, `doc-factory.js`, `ephemeral-window.js`, `web-security.js` all set `contextIsolation:true`, `nodeIntegration:false`; `webSecurity` never disabled). No fix needed.
- ✅ **`webviewTag: true` had no `will-attach-webview` guard** — the only actual `<webview>` use is the file-manager panel pointed at a fixed `http://localhost:3939`, but nothing stopped a future/injected `<webview>` from requesting `nodeIntegration`, a custom preload, or a disabled sandbox. Added a `will-attach-webview` handler in `main.js` that force-sets `nodeIntegration:false`, `contextIsolation:true`, `sandbox:true`, `webSecurity:true`, strips any `preload`/`preloadURL`, and disables `allowpopups` on every attached webview, regardless of what the requesting page asked for.
- ✅ **IPC handlers** — already unusually well-hardened: `wallet-rpc` has origin-allowlist gating with a user-approval prompt for unknown origins, plus a strict per-endpoint schema validator (`validateWalletSchema`) that rejects extra keys/wrong methods/malformed bodies. `web-fetch`/`web-search`/`social-rpc` all check `isInternalOrigin()`. No changes needed here — this is more thorough than the baseline ask.
- ✅ **RPC port hardcoding** — N/A. There is no exposed RPC port; `bucks-node.js` is called in-process via `handleRPC()`, not over a localhost socket, so there's no `8545`-style port to move to an env var in the first place.
- ✅ **`shell.openExternal`** — never called anywhere in the codebase (confirmed by grep). External navigation is instead blocked/redirected into the internal tab system via `setWindowOpenHandler` + `will-navigate`/`did-navigate` guards in both `main.js` and `tab-manager.js`. No fix needed.
- ✅ **`eval()` / `new Function()` / `@electron/remote`** — none found anywhere in `electron/*.js` (grepped clean). No fix needed.
- ✅ **`npm audit`** — found 2 vulnerabilities (high: `shell-quote` ReDoS; moderate: `tar` in a nested `cmake-js` dep). Ran `npm audit fix`, which also cleanly removed the unused `electron-updater` dependency (confirmed dead — it was already fully replaced by `cluster-updater.js`'s IPFS-native update path; only stale comments referenced it, no `require()` calls). Result: **0 vulnerabilities**, `npm ls` resolves cleanly, app still launches and runs its full startup sequence with no missing-module errors.

## Frontend

- ✅ **Broken imports** — none. Every `<script src>`/`<link href>` in `index.html` and every mini-app HTML file resolves to a real file.
- ✅ **XSS: `escapeHtml`/`escapeHTML` helpers didn't encode quotes** — this was the most serious frontend finding. Both helpers (`renderer.js`) round-trip through `div.textContent → div.innerHTML`, which encodes `& < >` but **not** `'`/`"`. Their output is routinely embedded inside single-quoted `onclick="...('...')"` attributes throughout `renderer.js`, so any value containing a quote could break out and inject script. Concrete exploitable paths: agent-answer markdown links (can echo scraped-webpage content — indirect prompt injection into the DOM), web-search result URLs, Nominatim geocode results, and cluster-peer-discovery metadata (`soulId`/`locality`, broadcast by other nodes on the network). **Fixed at the root**: both helpers now also encode `'` → `&#39;` and `"` → `&quot;`, which fixes every downstream call site at once. Also fixed the equivalent `_escHtml` helper in `nexus-panel.js` (same quote gap) and two spots that had **zero** escaping at all: the cluster-admit button's `d.soulId` (peer-broadcast, `renderer.js`), and `nexus-panel.js`'s swarm-peer card (`peer.model`/`lastSeen`/`locality`, also peer-broadcast) plus an agent tool-name field. Also fixed one spot where raw (unescaped) `p.lat`/`p.lon` from a Nominatim response were interpolated directly into an `onclick` handler instead of the already-sanitized local copies sitting right next to them.
- ✅ **XSS in `earth-maps.js` popup rendering** — `popupHTML()` concatenated Nominatim `display_name` (forward search + reverse "click anywhere" geocode) straight into Leaflet popup HTML with zero escaping. Added a local escape helper and applied it to both fields.
- ✅ **Hardcoded ports** — `:8765` (Soul Engine) was hardcoded independently 3 times across 2 files instead of reusing the existing `SOUL_ENGINE` constant; fixed the one in `renderer.js` (a straight duplicate a few thousand lines from the constant's definition) to use it. `:3939` (IPFS/Kubo proxy) is hardcoded in `index.html`'s `<webview>` `src=` and twice in `dweb-studio-renderer.js` — left as-is (no shared frontend config module exists to route these through, and introducing one is a larger change than this pass warranted); noted below for follow-up.
- ✅ **Missing error handling** — checked every `fetch()`/XHR call across `renderer.js`, `earth-maps.js`, `canvas-manager.js`, `messages-ui.js`, `agent-browser-control.js`, `universe-map.js`. All are already wrapped in `try/catch` or `.catch()`, directly or via their callers. No fix needed.
- ✅ **UI dead ends** — checked every named click handler across the renderer files; all resolve to real functions, and every `window.bucksAPI`/`window.nexusAPI` call matches something `preload.js` actually exposes. The one real dead end found: `window.BucksEarthMap`/`window.BucksUniverseMap` (defined only inside `bucks-universe.html`, never loaded by the shell) are referenced by "Navigate"/"Directions" buttons rendered inside chat answers in the main shell window, so those buttons silently no-op there. This is a pre-existing feature gap (map buttons were apparently written for a context where the map is embedded in-shell, which it currently isn't) rather than something safe to "fix" blind in this pass — flagged below for follow-up rather than papering over.
- ✅ **Messaging XSS (`messages-ui.js`)** — audited separately and found already solid: every peer-controlled field (name, message text, filename, peer ID) goes through its own local `escapeHtml` into plain text-node contexts, never reused in an attribute context. No changes needed.

## IPFS / libp2p

- ✅ **Bootstrap peers** — not hardcoded/placeholder; fully env-driven (`BUCKS_BOOTSTRAP_PEERS`), by design for a permissioned swarm (mDNS-LAN + manually-supplied cross-network peers, e.g. over Tailscale). No public-bootstrap fallback exists — correct for this app's private-cluster model, but means two default-config instances on different networks with no env var set will never find each other. Documented below, not changed (adding public IPFS bootstrap nodes would be wrong for a permissioned app like this one).
- ✅ **Peer discovery** — `mdns()` and `bootstrap()` are both genuinely wired into libp2p's `peerDiscovery` array (not just installed-but-unused deps). Confirmed live: "Discovered peer" / "Connected to peer" in the startup log.
- ✅ **`allowPublishToZeroTopicPeers` naming bug** — confirmed still fixed (correct spelling in place, no regression).
- ✅ **Helia startup error handling** — `createHelia()` is properly wrapped in try/catch with async/await, re-throws to a caller in `main.js` that catches it and degrades gracefully (IPFS-dependent features are skipped via `if (heliaNode && gossip)`, app doesn't crash).
- ❌ **No DHT configured** (`@libp2p/kad-dht` absent from dependencies and services). By design — the codebase compensates with manual peer dialing + Kubo peering — but it's a real scaling limit. Not changed (adding a DHT is a design decision, not a bug fix, and out of scope for a debug pass).
- ✅ **libp2p listen ports (4020/4021) hardcoded, no env override** — unlike `BUCKS_BOOTSTRAP_PEERS`/`BUCKS_CLUSTER_SECRET`/`BUCKS_CLUSTER_CIDN`, which are all env-configurable. Not changed in this pass (low risk — there's already a working random-port fallback on conflict) but flagged below since it's inconsistent with the rest of the file's configurability pattern.
- ✅ **`ipfs-bridge.js` port** — confirmed already configurable via `BUCKS_IPFS_BRIDGE_PORT`, with correct Kubo-detection-based fallback ordering and graceful degrade-to-null on total bind failure (verified live: bridge bound successfully on the second test run after the port freed up).
- ⚠️ **`forageForScarcity()` is a no-op stub** running on a live 60s timer — logs "Foraging for scarce data..." but its body doesn't actually query anything (its own comment admits this). Not a crash, just a described-but-unimplemented feature; left alone rather than guessing at the intended DHT-based implementation.

## Messaging (P2P Encrypted Chat)

- ✅ **Identity spoofing over the direct chat stream — fixed.** `chat-engine.js`'s `/bucks/chat/1.0.0` stream handler only destructured `{ stream }`, never checking the claimed `data.from` field against the actual Noise-authenticated remote peer of the connection. Combined with a *conditional* signature check (skipped entirely when we don't yet have the claimed sender's bundle on file) and an unauthenticated X3DH-init handler, this meant **any peer that could open a stream to you could impersonate any other peer ID**, establish a working encrypted session under that spoofed identity, and have the UI render it as a real conversation — with no cap on how many fake conversations could pile up. Fixed by capturing `connection` in the stream handler and requiring `data.from === connection.remotePeer.toString()` before dispatching to the X3DH or chat-message handlers at all; a mismatch is now dropped and logged. This is enforced at the transport layer (Noise handshake), so it can't be spoofed without the peer's actual private key. The existing Ed25519 envelope-signature check remains as a second, now-genuinely-meaningful layer of defense.
- ✅ **Same spoofing pattern in pre-key bundle gossip — fixed.** `handleBundleMessage()` trusted the self-reported `data.peerId` from the gossip payload instead of the gossipsub-verified publisher (`msg.from`) — every other gossip handler in the codebase (`ipfs-node.js`, `cluster-membership.js`) already uses the `msg.from.toString()` pattern correctly; this one didn't. Fixed to require `data.peerId === msg.from.toString()`, matching the established pattern.
- ✅ **Message signing** — genuinely Ed25519 (not the old secp256k1 scheme), correctly wired end-to-end. No changes needed.
- ✅ **Stale/misleading `provider: ollama` default + empty error log — fixed.** `agent-integration.js` hardcoded `provider: "ollama"` as its default status label and unconditionally probed `AGENT_SERVER_URL` (default `:3000`) on every chat-engine startup — but nothing ever starts a server on `:3000` by default (it's the same "unsigned, unaudited" experimental swarm-delegation target `main.js` deliberately gates behind `BUCKS_EXPERIMENTAL_SWARM=1`), and Ollama is never actually contacted anywhere in this file or the rest of `electron/`. The failure log was also printing an empty string (`e.message` is `""` on Node's `AggregateError` from dual-stack `ECONNREFUSED`, which is exactly what fires here). Fixed: default provider label changed to `"unavailable"` (accurate instead of misleading), the status-check log now falls back to the wrapped sub-error messages, and the initial `checkAgentStatus()` call in `chat-engine.js` is now gated behind the same `BUCKS_EXPERIMENTAL_SWARM=1` flag as the rest of that subsystem, so it no longer probes a port nothing listens on by default. Verified live: second test run's log now reads `Current provider: unavailable` with no failed-status-check noise, vs. the original run's misleading `provider: ollama` + blank error.
- ✅ **`AGENT_SERVER_URL` env-var collision — fixed.** `agent-swarm.js` and `agent-integration.js` both read `process.env.AGENT_SERVER_URL` defaulting to `:3000` (the experimental swarm target), while `cluster-membership.js` reads the *same* env var name defaulting to `:8765` (the real always-on Soul Engine, used for agent-signing calls during cluster admission). Setting `AGENT_SERVER_URL` to enable the experimental swarm layer would have silently redirected cluster-membership's signing calls to the wrong port. Renamed the swarm-only usages to a distinct `BUCKS_SWARM_AGENT_SERVER_URL`.
- ⚠️ **No replay protection on chat envelopes** (nonce generated but excluded from the signature and never checked on receipt) — mitigated incidentally by the Double Ratchet's forward-only key advancement, but that's a side effect, not a real anti-replay mechanism. Not fixed in this pass — the deeper issue below makes this lower priority to solve in isolation.
- ⚠️ **Double Ratchet has no skipped-message-key cache** — a single dropped or reordered message permanently desyncs that peer's receive chain (all subsequent messages fail to decrypt). This is a real correctness bug for any multi-hop/reconnecting swarm topology, but implementing a correct skipped-key cache in `signal-store.js` is a substantive crypto change that needs dedicated testing, not something to hand-edit in an audit pass. Flagged for follow-up, not attempted blind.
- ⚠️ **Chat history persisted in plaintext on disk** (`chat-history/<peerId>.json`), while session/ratchet state in `signal-store.js` already uses Electron's `safeStorage` wrapper. Not fixed here — changing the on-disk format needs a migration path for existing users' chat history, which is riskier to improvise than to flag.

## Networking / Multi-device

- ✅ **Chain sync validation** — confirmed solid. Every gossip-applied block/tx goes through PoW/hash/prevHash validation, per-tx signature + balance + nonce-replay checks, and full-chain adoption only happens if every block in the incoming chain validates and it's strictly longer. No unvalidated-trust-the-peer path found. No changes needed.
- ⚠️ **Trivial PoW difficulty + no reorg depth limit** (`bucks-node.js`, `DIFFICULTY = 4`, no checkpointing) — the validation logic is correct, but the cost of rewriting history is low, and any longer valid chain replaces the local one with no depth cap. This is a consensus-design question, not a bug to patch in an audit pass — flagged for a deliberate follow-up decision (checkpointing, difficulty retarget, or accepting the risk for a permissioned cluster).
- ✅ **Chain topic namespacing** — confirmed: `bucks-chain-<hash>` is derived from `BUCKS_CLUSTER_SECRET` (default: a fixed public string), not from the genesis block. This means all default-config installs land on the same topic by construction — a deliberate shared-default design, not a bug, but worth knowing: real network isolation requires operators to set a unique `BUCKS_CLUSTER_SECRET`.
- ❌ **NAT traversal / relay — absent.** No circuit-relay-v2, no AutoNAT, no hole-punching, no WebRTC transport. Two peers each behind NAT with no shared VPN (e.g. Tailscale) and no port-forwarding have no way to connect. Confirmed gap, not fixed — adding libp2p relay infrastructure is a feature addition, not a bug fix, and is flagged below for a deliberate decision.
- ✅ **Cluster updater signature verification** — confirmed fail-closed with no bypass: inert (no update ever offered) when `BUCKS_RELEASE_PUBLISHER_PUBKEY` isn't set; when it is, checks publisher ID match, Ed25519 signature over the canonical manifest payload, and a SHA-256 re-check of the downloaded artifact before install. No changes needed.
- ✅ **Cluster admission is confirmed local-only** — `admitMember()` has exactly one caller in the whole codebase, wired to an explicit UI "Add" button; the gossip receive path only ever *records* another node's admission decision, never triggers one itself. No changes needed.
- ✅ **`agent-swarm.js` experimental gating + unsigned messages** — confirmed exactly as documented in `main.js`'s own comment: gated behind `BUCKS_EXPERIMENTAL_SWARM=1`, and its gossip messages (task results, consensus votes) have no signature field or verification anywhere in the file — any peer on the mesh can forge results or stuff consensus ballots. This matches the code's own "unsigned, unaudited" label; not touched further since the file is already off by default and its own docs are honest about the risk.
- ✅ **`AGENT_SERVER_URL` default mismatch** — see Messaging section above (same fix, cross-referenced from both audits).

## Remaining (needs a deliberate decision, not a blind edit)

- **No DHT (`kad-dht`)** — would improve discovery beyond mDNS/manual-dial/bootstrap-env, but adding one is an architecture choice with tradeoffs for a permissioned swarm like this.
- **No NAT traversal / relay** — real gap for cross-network peers without a VPN; needs a decision on whether to add circuit-relay-v2/AutoNAT or keep requiring Tailscale-style connectivity.
- **Trivial PoW + unbounded reorg depth** in `bucks-node.js` — needs a deliberate consensus decision (checkpointing vs. accepted risk for a permissioned cluster), not a mechanical patch.
- **Double Ratchet has no skipped-message-key cache** — real correctness bug on message reordering/loss; needs a proper implementation + test pass in `signal-store.js`, not a quick edit.
- **Chat history stored in plaintext on disk** — fixing needs a migration path for existing users' history files.
- **`forageForScarcity()` is an unimplemented stub** running on a live timer — needs an actual DHT-scarcity-check implementation or should be removed/disabled until one exists.
- **`window.BucksEarthMap`/`BucksUniverseMap` chat-answer buttons no-op in the shell** — `earth-maps.js`/`universe-map.js` are only loaded inside `bucks-universe.html`, never by `index.html`; either embed the map in-shell or remove/redirect those chat-answer buttons.
- **Mini-app CSP hardening** — `bucks-calc/notes/clock/converter/qr/template-dashboard/portfolio.html` all rely on inline `<script>` with no CSP of their own; worth a follow-up pass to either externalize their scripts (enabling a real per-route CSP) or add scoped nonce-based policies.
- **`:3939` IPFS-proxy port still hardcoded in 3 places** (`index.html`, `dweb-studio-renderer.js` ×2) with no shared frontend config constant — lower priority than the `:8765` fix already applied, since there's no existing config module to route it through.
- A `data/quran_source.json`/`.sha256` pair already exists in the repo as a pre-existing, gitignored proprietary asset per prior project history (real content never shipped, only a placeholder ships) — noted for completeness, not touched, no action needed here.
- **Rotate secrets in git history** — carried over from prior project notes (Gemini API key + `CLUSTER_SECRET` still in git history from before the production cleanup); unrelated to this pass but still outstanding.

## Verification method

Every fix above that touches `main.js`, `chat-engine.js`, `agent-integration.js`, `agent-swarm.js`, `renderer.js`, `nexus-panel.js`, or `earth-maps.js` was syntax-checked with `node -c`. The full app was launched twice via `npx electron .` (background process, logs captured, then cleanly terminated by PID — never a blanket `pkill` that could have hit an unrelated running instance) to confirm: no CSP violations, no missing-module errors, Helia/libp2p/gossipsub/chat-engine/cluster-membership/cluster-updater all initialize cleanly, and the `[Chat] Agent Integration` status line changed from the misleading `provider: ollama` (+ blank error) to the accurate `provider: unavailable` (silent, gated) between the first and final run.
